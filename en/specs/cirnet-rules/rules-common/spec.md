# Common Rules rebuild specification

Historical migration on 2026-11-14. Replace Governance with portable Markdown
guidance in the existing `rules-common` worktree. Use six local products as
read-only evidence under their own ownership, plans and test policies.

- Deliver standalone English `AGENTS.md`, `CLAUDE.md` with `@AGENTS.md`, four
  topic guides, three optional skills, manual setup and a dated source map.
  The map is a source snapshot and each product owns its contracts and releases.
- Verify backup refs before deleting tracked legacy application, registry, CI,
  assets and obsolete docs. Protect user data, Git, license, attributes, ignore
  rules and relevant attribution. Use Markdown without runtime tooling.
- Read product docs, manifests, source and tests. Check branch and product
  status before and after, client scope against official sources, preferences,
  UTF-8, links, skill metadata, adapter and whitespace. Review typo, API and
  FPGA scenarios and record native loader/E2E separately.

Scope covers local Markdown migration and static checks. Product edits, builds,
tests, Git staging or publication, installs and physical work are outside scope.
