# Task specification template

Use these prompts for task-specific requirements in the Task Continuity
checkpoint or for an independently useful specification in its owning repository.

- Problem and intended behavior, with a concrete example when helpful.
- Goals, non-goals, owner boundaries and authorized scope.
- Existing contracts/dependencies that must remain compatible.
- Design decisions and material alternatives or tradeoffs.
- Acceptance checks tied to observable behavior and failure cases.
- Required English/Vietnamese documentation updates.
- Evidence limits: source review versus runtime, release or physical qualification.

Keep the spec and its translation aligned when decisions change. Record observed
test results separately; a requirement is not evidence that a check passed.
